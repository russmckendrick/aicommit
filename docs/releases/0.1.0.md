# aicommit 0.1.0

The first release built around an interactive terminal UI. Plain `aic` now opens a full-screen interface where you stage individual hunks, watch the message stream in, edit it, split the staged changes into several commits, commit, and push, all without leaving it. Underneath, splitting works hunk by hunk, the HTTP providers stream, `--json` and `--quiet` make `aic` easy to script, and messages follow each repository's existing style.

## Upgrading

- **`aic` opens the terminal UI** when it runs in an interactive terminal. Use `aic --fast` (or `-f`) for the previous prompt-based flow, or set `AIC_TUI=false` to make that the default. Scripts, pipes, Git hooks, and `--yes`, `--dry-run`, `--amend`, `--json`, and `--quiet` are unaffected and never open it.
- **Default models changed** (see below). Your configured model is kept; switch with `aic setup`, `aic config set AIC_MODEL=…`, or the terminal UI's settings (`,`).
- **`~/.aicommit` is rewritten without default values** the next time `aic` saves it, so future default changes reach you. Values you set are kept.
- **Icons:** the terminal UI uses Nerd Font icons by default, following `AIC_REMOTE_ICON_STYLE`. Set `AIC_ICONS=unicode` if your terminal font isn't a Nerd Font.

## Terminal UI

- `aic` now opens a full-screen terminal UI, built with `ratatui`, whenever it runs in an interactive terminal. See [Terminal UI](../tui.md).
- New `-f`/`--fast` flag skips the terminal UI and uses the quick prompt flow. `AIC_TUI=false` makes the prompt flow the default, and `--tui` opens the UI on demand. Scripts, pipes, hooks, `--yes`, `--dry-run`, `--amend`, `--json`, and `--quiet` never open it.
- Settings screen (`,`): change provider, model, API key, API URL, message style, push, theme, and icons, saved straight to `~/.aicommit`.
- First run: when the provider needs an API key and none is set, `aic` opens on the settings screen with the key field selected instead of exiting with an error.
- Commit screen: a staged/unstaged tree where `space` stages or unstages individual hunks, a syntax-highlighted diff with word-level changes, and a message panel that starts writing as soon as the TUI opens, streaming where the provider supports it.
- Split screen: proposed commits appear as columns; move hunks between them with `←`/`→` or by dragging with the mouse, add or merge commits, and messages for changed commits are rewritten automatically.
- Command palette (`ctrl-k`), help overlay (`?`), live theme switching (`t`), subject-length counter, stale-message warning, mouse support, and a layout that adapts to the terminal width.
- New config keys: `AIC_TUI` (default `true`), `AIC_THEME` (`auto` or any `aic map` theme), and `AIC_ICONS` (`auto`, `nerd`, or `unicode`).
- Committing and pushing happen inside the TUI. After `c`, a result screen shows the hash, branch, line counts, and message, then offers to push to the remote (with its Git host icon); pick a remote when there are several. A rejected push can be rebased and retried with `r`. `enter` goes straight on to the next commit when changes remain. On quit, a summary of the session's commits is left in the scrollback.
- Split commits are created inside the TUI too, with progress, and pushed from the same result screen.
- The header shows the branch's sync state with its upstream (ahead, behind, or diverged), checked in the background. Being behind no longer stops the TUI from opening.
- The first message starts writing itself a moment after you stage something, if nothing was staged when the TUI opened.
- Nerd Font icons by default (`AIC_ICONS=auto`): file-type icons in the tree, provider icons in the header (GitHub Copilot, Azure, and Apple logos; brand-coloured icons for the rest), and git icons, all chosen to work with any Nerd Font, including Ghostty's built-in symbols. `AIC_ICONS=nerd` adds the real OpenAI and Claude logos for Nerd Fonts 3.5+, and `unicode` works in any font.

## Streaming

- `openai`, `azure-openai`, `groq`, `ollama`, custom OpenAI-compatible endpoints, and `anthropic` now stream the final commit-message request. While it is written, the status spinner previews the subject line instead of a rotating status message.
- Chunk summaries for large diffs stay non-streaming; only the request that produces the message you see streams.
- Command-backed providers (`claude-code`, `codex`, `copilot`, `apple`) are unchanged and return the whole message at once.

## Machine-readable output

- New `--json` and `--quiet` flags on `aic`, `aic review`, and `aic pr` print only the result to stdout, for scripts, CI, and coding agents. See [Automation](../automation.md).
- In either mode `aic` never prompts and only commits when `--yes` is also passed. `--json --yes` reports the full commit hash.

## Hunk-level split commits

- The split flow now groups **hunks**, not files, so one file can be split across several commits. The model sees each hunk tagged with an ID (`src/ui.rs#2`) and returns hunk IDs; replies in the old file-based format still work.
- Split commits are created by snapshotting the index, resetting it to `HEAD`, and applying each group's patch with `git apply --cached`. The working tree is never touched.
- The split flow is no longer blocked when a staged file also has unstaged changes.
- If a split commit fails part-way, the remaining changes are restored to the index instead of being left unstaged.
- Files hidden by `.aicommitignore` now stay staged after a split, instead of being unstaged.
- A single file with two or more staged hunks can now be split.

## Repository style matching

- Generated commit messages now follow the habits of the repository they land in. `aic` reads the last 50 non-merge commit subjects and tells the model which scopes are already in use, how descriptions are cased, whether subjects end with a full stop, and how long subjects usually are.
- Needs at least 8 commits of history, and never overrides `AIC_EMOJI` or the commit convention. Turn it off with `AIC_REPO_STYLE=false`. Custom prompt files opt in with the new `{{repo_style}}` placeholder.

## Updated default models

| Provider | Previous default | New default |
|----------|------------------|-------------|
| `openai`, `azure-openai` | `gpt-5.4-mini` | `gpt-6-luna` |
| `anthropic` | `claude-sonnet-4-20250514` | `claude-sonnet-5-5` |
| `groq` | `llama-3.1-8b-instant` (retired by Groq) | `openai/gpt-oss-20b` |
| `ollama` | `llama3.2` | `gpt-oss:20b` |

- `aic setup` and `aic models` suggest current models: GPT-6 Luna, Sol, and Astra; Claude Sonnet, Haiku, and Opus 5.5 and Fable 5.1; GPT-OSS on Groq and Ollama.
- Existing configs keep the model they have. To move to the new default, run `aic setup` or `aic config set AIC_MODEL=<model>`, or pick it in the terminal UI's settings.
- `--provider` still swaps in the new provider's default when your configured model is any current or earlier default.
- GPT-6 models get the same request parameters as GPT-5 (`max_completion_tokens`, no sampling parameters).

## Config file keeps only your changes

- `~/.aicommit` now stores only settings that differ from the defaults. Previously `aic setup` and `aic config set` wrote every key, which froze each default at the value it had on the day you ran them, so later default changes (such as the new models) never reached you.
- The next time `aic` writes the file, values equal to the current defaults are removed. Values you changed are kept, and a model that was an older default is kept too, since `aic` can't tell whether you chose it.
- With no model stored, the model is the default for the configured provider.

## History file reliability

- `~/.aicommit-history.json` is now written to a temporary file and renamed into place, so two `aic` processes writing at once can no longer leave it half-written.
- A history file with stray characters after the entry list (left by such a race) is read normally again. A file that cannot be read at all is moved aside to `.aicommit-history.json.corrupt-<time>` and a new one is started, instead of every later commit failing to save history with a warning.
